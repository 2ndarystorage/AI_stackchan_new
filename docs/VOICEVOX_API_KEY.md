# VOICEVOX（tts.quest）のAPIキー設定

## 必要かどうか

このプロジェクトはVOICEVOXエンジン本体ではなく、非公式の外部サービス`tts.quest`のv3 APIを使います。提供元の説明では、キーなしでも間隔制限付きの低速枠を利用でき、有効なキーとポイントがあれば高速枠になります。キー設定だけで本体のメモリ不足・TLSの確保失敗が解消するわけではありません。

- [低速枠の提供元説明](https://voicevox.su-shiki.com/su-shikiapis/ttsquest/)
- [提供元から案内されているv3 API仕様](https://github.com/ts-klassen/ttsQuestV3Voicevox)

`isApiKeyValid: NG`だけでは「文字列が間違っている」とは断定できません。v3仕様ではポイントが残っていない場合もfalseになります。429は再送間隔の制限で、`retryAfter`以上の待ちが必要です。キーを何度も発行し直したり、合成要求を無制限に再送したりしないでください。

## 取得・利用登録

1. [キー取得ページ](https://su-shiki.com/api/)を開き、「VOICEVOX用のapiKeyを取得する」にチェックして手動で発行します。
2. 案内に従って[VOICEVOX用API利用登録](https://voicevox.su-shiki.com/su-shikiapis/ttsquest/apikey/)を行います。すでに取得したキーを使う場合は、SHA-256ハッシュを申請フォームへ登録する手順です。提供元の説明ではGoogleアカウントが必要です。画面の案内と利用条件を確認してください。
3. キーを本体へ設定し、次の意図した短い合成で有効判定を確認します。キーやGoogleフォームの回答編集URLは公開しないでください。

提供元は自動スクリプトでのキー生成を禁止しています。今回こちらからキー生成・申請・Googleログイン・既存キーの取得は行っていません。旧高速API案内にあるdeprecatedなv2 URLへ、本体のv3接続先を変更する必要もありません。

## 本体への設定と注意

信頼する同一LANで本体の`/apikey`を開くと、OpenAI／VoiceVox／Speech to Textの3欄があります。ただし現行の`handle_apikey_set()`は**空欄も含めて3項目すべてを上書き**します。VoiceVoxだけを入力し、他を空欄のまま送ると既存設定を失うため、3項目の値が手元にある場合だけ全欄を確認して保存してください。フォームやAPIをインターネットへ公開しないでください。既存キーは読み取り・ログ出力していません。

microSDの`apikey.txt`を使う場合は、元ファイルを手元で退避したうえで**2行目のVOICEVOXキーだけ**を更新し、1行目のOpenAIキーと3行目のSTTキーを維持してください。起動時にこのファイルが読み込まれるため、Web設定と内容が食い違うと再起動時に戻る可能性があります。Web設定の再起動後保持も今回の試験では検証していません。

キーはこのチャットへ貼らず、ユーザー自身で入力してください。キーなしの低速枠を使う場合も、提供元の利用条件・話者ごとのライセンス・再送間隔を守ってください。
