# v9.17 スピーカー出力・音量修正と音声専用LAN診断

更新: 2026-11-01。**新ファームの実機での音出しは未確認**です。コード上の無音を見逃す欠陥と過剰な減衰を修正し、通信・生成音声と切り離して出力を試験できるようにしました。実機に残るTLS失敗の根本解消は、この版でも保証していません。

## 今回のログ

- 起動は`MP3 decoder task ready ... v9.15`です。前回配布のv9.16は、このログを出した本体にはまだ反映されていません。
- 複数の文で取得完了・全入力消費・想定に近い時間・`reason=natural`まで進んでいます。しかし、これはスピーカーから実音が出た証明ではありません。
- 合成／完成待ちの一部ではX509 -9984に加えてBIGNUM -16（メモリ確保失敗）が出ています。NGと429による無料枠／キーの制限、生成待ちの長さも別に残っています。これらを物理出力の無音と一括して扱いません。
- `Failed to deserialize JSON`はロール設定読込後に既定値へフォールバックする箇所であり、この表示だけで今回の無音原因とは判断していません。

## 判明したコード上の問題と修正

1. `AudioOutputM5Speaker::begin()`が無条件にtrueを返していました。さらに固定依存M5Unified 0.1.16の`_play_raw()`は、begin失敗／タスクハンドル未生成でもtrueを返す経路があります。そのためPCMを読み進めても出力できていないケースを成功扱いできました。アダプター開始時に実際のbegin・稼働状態・タスクハンドルを確認し、開始失敗時は再生開始を拒否。途中で稼働状態を失った場合もデコーダを停止し、`reason=output-error`と画面エラーで区別します。発話開始前にもチェックし、開始できないのに合成キューを投入しません。固定依存のprotectedタスクハンドルを読み取り専用の基底メンバーポインターで確認し、不正なダウンキャストやレイアウト書き換えは行いません。依存更新時にはこの確認も再検証が必要です。
2. 音量をmasterと仮想channel0の両方へ同じ値で設定していました。M5Unifiedは両方を二乗して乗算するため、例えば51/255では相対ゲイン0.2^4=0.0016（0.16%）まで低下します。ユーザー音量はmasterだけに適用し、channel0と確認音channel7を255に固定。51なら0.2^2=0.04（4%）で、旧実装との比は25倍です。意図したレベル0のミュートは保持し、勝手に解除しません。
3. `/setting`とタッチの音量を共通経路へ統一し、`vol`と`volume`を整合させてNVS commit。旧volume=0の読み込みもミュートとして保持し、初期値未設定の読み取りは安全な既定値を用意しました。`/setting`で音量引数がない場合は現在値を保持します。
4. このCore2用ビルドは内蔵スピーカーを明示し、外付け選択を無効化。出力サンプルレートは48kHzにします。従来のexternal_spk=trueだけでCore2の出力先が必ず誤ると確認したわけではなく、構成を明確にする変更です。外付けSPKを使う構成はこの版の対象外です。PMICのアンプ制御はM5Unifiedの既存コールバックを維持します。
5. 再生終了時に`PCM submitted`（キューへ渡した16bitサンプル要素数）、`peak`（PCM入力ピーク）、`output_fault`、master、channel0を記録。これも実際の音圧や配線・アンプ・スピーカーの正常性を直接測るものではありません。

## Wi-Fi内の音声診断

本体へv9.17を書き込んでから、同じWi-Fiのブラウザで`http://stack-chan.local/audio`（または`http://本体IP/audio`）を開きます。

- `GET /audio`: 診断ページ。
- `GET /audio_status`: ファーム版、検出ボード・PMIC、I2Sピン、master/channel0、ミュート、スピーカー／マイクの稼働、前回PCM送信数・ピーク・出力異常をJSON表示。APIキー、Wi-Fi認証情報、会話内容は返しません。
- ページの**スピーカーテスト（API不要）**: 明示クリックにより660Hzと880Hzを各150ms出力要求。合成API・TLS・MP3・課金を使いません。ニュース／会話中は409で拒否します。
- テストはミュート中でも一時的にmaster=102・channel7=255へ変更します。説明を読んでから実行してください。終了時・開始失敗時とも元のmaster／channel7へ戻し、マイクを復帰させます。結果の「出力要求」は聴感確認済みという意味ではありません。
- POSTと専用ヘッダーを要求し、通常の外部Webフォームからの起動を拒否。認証・暗号化は追加していないため、信頼する同一LAN内でのみ使用し、ポート転送等でインターネットへ公開しないでください。

これは**音声専用の状態表示／試験**で、会話ログや起動ログ全体をブラウザ配信する機能ではありません。既存Webサーバーを使うため、メイン処理が同期通信中なら応答が遅れる場合があります。

## 版の取り違え対策

画面左上は`v9.17`。フラッシャーはindex→main→firmware-dataの読み込みURLに版を付け、HTMLの期待版とファームの版が一致しなければ書き込みを拒否します。シリアルの旧起動バナーも読み取り、配布版との不一致を表示します。ブラウザの旧キャッシュや別フォルダ／別USBポートでの書き込み取り違えを確認しやすくします。
