# 最新配布v9.23の実機追加試験

## 対象と許可

ユーザーから「USB接続したので、最新ソフトのDLから動作確認まで自動で実施」と依頼を受けて実施しました。定期タスクは削除済みのままで、再作成していません。

- 配布リポジトリの専用ブランチ先端`a6b5e6692b4e3561b548dcb49032158dc62ccabc`をGitHubで確認し、そのコミットのZIPを新たにダウンロード。ZIP CRCと全配布パーツのサイズ／SHA-256を検査しました。
- 使用したのは既存配布v9.23の`firmware.bin`（3,535,568 bytes、SHA-256 `4ed098e399b63b0330dfcfc4e6d09df4083ae5ac2d1905aeb6367a27e9b97646`）。ローカル再ビルドとの差異は既知で、配布を再生成・差し替えしていません。
- 接続時の本体はv9.21、音量レベル0・master=0（ミュート）、マイク稼働でした。パーティション表とOTA選択情報を確認し、選択中のapp0（`0x10000`、サイズ`0x640000`）のみを対象にしました。
- 現在のapp0を復旧用にローカルの非公開ファイルへ退避。NVSやSPIFFSは読み出さず、Gitへバックアップを含めていません。
- v9.23のアプリのみを書き込み、esptoolのハッシュ照合に成功。ブートローダー・パーティション表・OTA選択・NVS・SPIFFSは書き換えていません。

## v9.23の結果

- 起動ログとWeb診断がv9.23で一致。Wi-Fi接続と元のミュート設定が維持され、MP3デコードタスクも作成されました。
- **バージョン表示のちらつき:** ユーザーから「v9.23が見えて、ちらつかない」と回答をいただきました。今回の実機表示条件では改善を確認できました。
- **起動ダンス:** 開始時の空きヒープ21,504 bytesで、60,000 bytesの下限を満たさず`skipped: low heap`になりました。完走とは扱いません。
- **TLS接続（HTTP・合成API要求なし）:** `connected=false`、`error=-16256`、`verify_flags=0`、`allocation_failure=true`、確保失敗1回。シリアルの最終失敗サイズは172 bytesでした。証明書flagsによる拒否ではなく、今回はメモリ確保失敗を観測しています。
- **API不要の2音テスト:** HTTP 200、`offline test queued=1 restored_master=0`。出力要求を確認し、元のミュートへ戻りました。この試験分の実際の可聴性は、ユーザーからまだ個別に確認いただいていません。
- **BLE開始:** `/ble`を1回実行。`start receive mode heap=19556 largest=12788`の後、30秒でHTTPタイムアウト。続くWeb状態取得も5秒でタイムアウトしました。広告開始ログはなく、BLE初期化完了・GATT接続・データ転送は確認できていません。BLE無線通信成功とは扱いません。
- TLSで確保失敗を確認したため、ニュース・天気・列車・転送ニュース・会話の合成要求を追加で送ることはしていません。合成API要求は0回です。
- ウェイクワードの実音声検出・会話開始も未試験です。機能があることと、今回の実機で動いたことを混同しません。

## 切り分けと復旧

BLE対応ビルドのメモリ予約が候補の一つですが、TLS確保失敗・低メモリとBLE開始後の無応答を、すべて単一の原因と断定していません。NimBLE初期化コードではClassic BTのメモリ解放が初期化時に行われ、同期完了までの待機に明示的な期限がありません。初期化のどの内部処理で停止したかは今回のログだけでは特定できません。

ユーザーに結果を伝え、「元のv9.21へ戻す」と明示回答をいただきました。退避した元のapp0イメージのチェックサムと検証ハッシュが有効であることを確認し、元のapp0全体を同じ位置へ復元。書き込み後のハッシュ照合も成功しました。フラッシュ操作の対象はアプリ領域のみです。

- 復元後の起動ログとWeb診断はv9.21。元のWi-Fi接続、音量レベル0・master=0・マイク稼働を確認しました。資格情報の値自体を読み出して照合してはいません。
- 起動時空きヒープは239,520 bytes。ダンス開始時は97,148 bytesで、100フレームを`skipped=0 errors=0`で完走しました。
- 復元後のAPI不要TLS接続テストは`connected=true / error=0 / verify_flags=0 / allocation_failure=false / failed_allocations=0 / http_requests_sent=0`でした。
- v9.23のちらつき改善はユーザー確認済みですが、復元後はv9.21の表示方式へ戻ります。現時点の本体がv9.23であるとは案内しません。
- BLE試験用に準備したローカルWebサーバーは停止済み。MacのBluetooth権限は未許可状態と確認しましたが、権限変更やGATTスキャン／接続は行っていません。シリアル監視も試験終了時に閉じます。

今回の試験は「最新版の全動作成功」ではなく、v9.23の通信不具合を検出し、ユーザー指定で元の版へ戻した試験です。設定・実機の現状を守るため、ニュースや合成要求を追加反復していません。[機密情報を含めない試験数値](DEVICE_TEST_V923.json)も保存しています。

回帰20件とフラッシャー版整合試験は再実行して成功していますが、これらの成功は今回の実機TLS・BLEの失敗を打ち消すものではありません。APIキーの取得方法は[別紙](VOICEVOX_API_KEY.md)へ記録しました。キー設定を変えてこのメモリ不足を回避したと表現しません。
