# v9.24 通常動作とBLE転送の分離（開発版）

## 状態と目的

2026-11-03、ユーザーの「BLE使用時と通常の動作は設定を分けて同時に動作しないように」に対応したソース・ローカルビルドです。**v9.24の実機試験・書き込み・音出し・課金API試験は実施していません。** 本体の最後に確認した状態は、v9.23試験後に復元したv9.21です。

v9.23ではBLEを初期化していない通常起動でも内部RAMが少なく、実機でTLS確保失敗とBLE開始後の無応答を観測しました。今回の対策は通常起動でBluetooth予約メモリを解放し、BLEを別起動に隔離するものです。これにより実機のヒープ不足やBLE起動不良が解消するかは、まだ測定していません。静的オブジェクト等のメモリが全てなくなる、v9.21と同じ空き容量になる、という保証ではありません。

## 動作モード

| 項目 | 通常モード（既定） | BLE転送専用モード（一回だけ） |
| --- | --- | --- |
| Bluetooth | コントローラ未初期化の状態でBTDM用メモリを解放 | NimBLE 1.4.3を初期化して受信 |
| Wi-Fi / Web / TLS | 既存機能を起動 | 起動しない。Web無応答は仕様 |
| 音声 / 会話 / ニュース | 既存機能を起動 | マイク・スピーカーを無効化。合成・デコード・ウェイクワードの初期化も行わない |
| Avatar / ダンス / スケジューラ | 既存機能を起動 | 起動しない。専用の状態画面のみ |
| データ | 保存済み転送ニュースを読める | 受信と保存のみ。読み上げや完了音は鳴らさない |
| 切替 | 次回BLE起動を設定して再起動 | 終了時は通常起動へ再起動 |

Bluetoothメモリの解放は同一起動中には元に戻せません。そのため、通常動作の途中でNimBLEを初期化する旧経路を廃止し、**再起動を資源の境界**にしています。[ESP-IDF 4.4のメモリ解放仕様](https://docs.espressif.com/projects/esp-idf/en/release-v4.4/esp32/api-reference/bluetooth/controller_vhci.html#_CPPv418esp_bt_mem_release13esp_bt_mode_t)。

## v9.24を書き込んだ後の操作

1. 通常モードで本体の `http://stack-chan.local/mode` または `http://本体IP/mode` を開きます。本体ホームにも設定リンクがあります。
2. 「BLE転送専用モードへ切替」で確認に同意します。音声・合成・発話待ちがある場合は409で拒否し、終わってから操作します。
3. 保存成功時だけ202を返し、約750ms後に再起動します。この間は通常loopの追加処理を止めます。
4. 本体に `BLE transfer only` / `Wi-Fi / voice: OFF` / `WAIT (3 minutes)` が出たら、転送ページの「BLEで送信」を使います。**旧「受信モードを開始」ボタンは使いません。** `GET /ble` は表示専用で、勝手には切り替わりません。
5. 既存GATTサービス名 `StackChan-Digest` とUUID、`BEGIN:<bytes>` / DATA / `END`、STATUS通知は維持しています。受信は最大60KiB、待ち受けは広告開始から3分です。
6. 保存成功または保存エラーの15秒後、受信時間切れの3秒後、本体Cボタンで通常モードへ再起動します。Cボタンはキャンセルのため、未保存データは破棄します。保存処理の途中には割り込みません。

BLE専用起動の間はWi-Fi接続もWebサーバもありません。`/audio_status`などの応答を待って再試行せず、本体画面・シリアル・GATT STATUSを確認します。通常復帰後はDHCPでIPが変わる可能性があります。

切替は `POST /ble` と `X-Stackchan-Mode: ble` ヘッダーが必要で、設定ページから同一オリジンで呼び出します。公開インターネットへの本体Web公開や、信頼しないLANでの利用は避けてください。

## 設定保持と異常時

- 次回起動用の設定はNVSの専用 `runmode` 名前空間・`next` キーだけに保存します。既存のWi-Fi・APIキー・音量・スケジュール設定とは分離しています。
- 次回BLE指定は、BLE初期化**前**に通常へ書き戻してcommitします。読出し・解除に失敗した場合はBLEへ進みません。BLE中の電源断・クラッシュ後の起動も通常へ戻る設計です。
- 通常モードのBTメモリ解放に失敗した場合は起動を停止し、低メモリのまま通常動作を続けません。ログに解放結果と直前直後の空き容量を記録します。
- NimBLE初期化は別タスク、起動待ちは最大15秒です。同期待ちが戻らなくてもmain側から通常へ再起動します。動作中のBLEタスクを強制削除してWi-Fiへ移行したり、同一起動中にdeinit待ちを続けたりしません。
- BLE専用経路ではNVSの事前初期化エラーで中止します。新しいモード処理でNVS消去は行わず、保存先SPIFFSも `begin(false)` として自動フォーマットしません。
- END・データ書込・途中切断の状態変更を同じmutexで扱い、保存開始後のバッファを切断処理で破棄しないようにしました。状態・受信数の共有はatomicです。
- 保存先と最大10件の保持方針は従来どおりです。フルフラッシャーのNVS/SPIFFS初期化は別操作であり、モード設定の保持保証と混同しません。
- CA/SNI検証とv9.18のTLSメモリ方針、顔キャンバス内のバージョンバッジ合成を維持しています。v9.23のちらつき改善はユーザー確認済みですが、v9.24の表示は未確認です。
